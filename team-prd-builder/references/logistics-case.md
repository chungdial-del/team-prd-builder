# 通用物流情境

本文件使用完全虛構的情境，示範物流需求訪談的問題設計。它不引用真實客戶、內部資料名稱、專案文件或作業政策。只有專案涉及物流時才讀取；各項規則仍由該專案的正式來源與產品決策確認。

## 虛構情境與確認問題

假設一個配送工具接收訂單資料與資源資料，由操作人員檢查方案，再交由另一個系統處理。下表列出可以追問的問題，不預設業務答案。

| 虛構情境 | 需要確認的問題 | 規格應記錄的內容 |
| --- | --- | --- |
| 訂單資料與資源資料在不同時間更新 | 哪個版本組合可以一起計算？資料缺漏時如何處理？ | 來源、版本關聯、有效時間及缺漏結果 |
| 訂單數量與車輛容量使用不同單位 | 是否需要換算？公式由誰維護？在哪一步取整？ | 單位、換算依據、取整時點與邊界案例 |
| 可用資源不足以完成全部配送需求 | 哪些限制不可違反？是否可以部分安排？由誰確認？ | 硬限制、警告、無解結果及人工決策責任 |
| 任務跨越日曆日期 | 工作日如何定義？時間依哪個時區解讀？ | 時間欄位語意、跨日規則及驗收案例 |
| 操作人員修改已確認方案 | 哪些狀態允許修改？其他操作人員如何取得最新版本？ | 允許動作、版本衝突與拒絕後結果 |
| 下游系統未明確回覆接收結果 | 如何確認結果？哪些條件允許重送？ | 查詢方式、未知狀態、重送條件與可觀察證據 |

## 使用方式

從專案材料預填已有答案。對未確認條件建立Q，記錄責任人、受影響FR與合理選項。產品決策確認後才寫入BR、圖解及AC。

另依專案需要追問資料品質、權限、取消、復原、併行及驗收資料。沒有正式依據時，不填固定容量、換算比率、分配公式、時區或外部介接政策。
