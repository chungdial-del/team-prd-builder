# PRD 主文件與規格卡

## 依專案規模調整的章節

| ID | 章節 | 內容與產物 |
| --- | --- | --- |
| C01 | 產品摘要與文件治理 | 目的、讀者、負責人、來源權威、核准範圍 |
| C02 | 問題與成功定義 | 現況、痛點、價值、指標、量測、基準與目標 |
| C03 | 範圍與優先順序 | MVP、後續與不做、依賴及分期 |
| C04 | 使用者與操作權限 | 角色、任務、資料範圍與讀寫發布等動作 |
| C05 | 產品功能架構 | 模組、共用能力、外部系統、責任邊界 |
| C06 | 歷程與操作流程 | 正常、交接、分支、反向及復原 |
| C07 | 資料與共用規則 | 名詞、單位、來源優先序、公式及狀態 |
| C08 | 功能需求與介面 | 功能卡、畫面、欄位與選用Mockup對照 |
| C09 | 系統互動與功能時序 | 關鍵系統互動、非同步、逾時與重試 |
| C10 | 品質驗收與發布 | NFR、AC、發布監控與復原 |
| C11 | 風險決策與追溯 | 假設、待決、責任、來源映射及變更 |

不是每個小功能都需要11章；不適用可註明原因或省略，不能放空章冒充完整。原章節映射使用穩定ID，不把重排後的頁碼當唯一定位。

依references/writing-principles.md建立五層。預設正文順序為C01／C02／C03、C04／C06、C05／C07／C08、C09、C10／C11。重排不改穩定ID。所有章節需有五層定位。L4只記已提供的技術契約；缺少時列Q，不自行補底層架構。

## 功能規格卡

每項FR包括：標題、User Story、主要角色、目標、範圍／優先順序、來源及規格狀態、前置條件、觸發、欄位與輸入、正常步驟、成功結果、拒絕或警告、取消或恢復、畫面ID、規則ID、圖ID、AC ID及未決阻擋。選用Mockup另記版本、確認範圍、畫面與來源；沒有不阻擋撰寫。

給定前置及輸入，預期應唯一。AC拆成必要的正常、反向、權限、邊界、失敗、併行、歷史或下游案例，記錄Given、When、Then與執行狀態。不是所有功能一律需要每種類別，但省略適用類別要有理由。剛撰寫的AC均未執行。

核心邏輯與狀態先用圖表表達。用短句補條件、公式、單位及例外。保留目標GO→FR／BR→AC→CT／TC追溯。測試預期需PM確認，不能從程式結果反推。最後以獨立的機器驗證章節展示測試檔、命令、結果及未驗證範圍。

## 共用規則

BR包括：陳述、適用FR、來源、已確認／提案／待決／被取代、觸發與生效條件、硬／軟／偏好、阻擋階段、例外資格及明確結果。數值規則另列單位、範圍、公式、取整與完整算例。

資料字典包括業務語意、來源欄位、型別、單位、空與零、唯一識別、日期／時區及對帳範圍。狀態表包含物件、狀態、可用動作、轉移條件、拒絕後不變性及稽核。不為缺少契約的外部系統設計想像中的接口。

## 開發可用與文件可讀是兩件事

能輸出DOCX只表示模型結構可呈現；還需渲染並檢查每張圖的說明及每頁版面。開發交付候選另需確認來源、無阻擋待決、相應規則、足夠AC及產品／工程／QA審閱證據。沒有HTML或Mockup不是阻擋；檢查器不能代替人確認業務正確、工程估時或測試結果。
