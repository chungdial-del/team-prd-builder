# 訪談與確認

## 盤點表

每個資訊項目記錄：題目、答案摘要、來源ID與定位、確認角色、狀態、影響的FR、下一步。

狀態區分「已有來源但未核准」「已確認」「提案」「待決」「相反指示」「不適用」。不要把模型自信分數當成核准證據。

問題格式：現在知道什麼；還缺什麼；為何影響開發；合理選項及代價；誰能答；阻擋哪一項功能。已有材料能回答的問題先預填，不重問。

## 通用題庫

| 類別 | 要問的問題 |
| --- | --- |
| 問題與價值 | 現在如何完成工作？最痛的步驟是什麼？為何此時解決？ |
| 使用者與角色 | 誰是主要使用者？誰審核與管理？各角色可讀與可做什麼？ |
| 成功 | 哪個可觀察改變代表成功？現有基準和資料來源是什麼？誰確認目標及時限？ |
| 範圍 | 本期必須有什麼？可以延後什麼？明確不做什麼？ |
| 操作 | 如何開始及完成？在哪裡交接責任？取消、退回及重做如何處理？ |
| 資料 | 來源、維護者與使用範圍是什麼？空、0、未提供與錯誤如何區分？衝突來源誰優先？ |
| 規則 | 單位、公式、取整及邊界是什麼？何時生效？硬限制、警告、偏好及例外如何區分？ |
| 介接 | 誰呼叫誰？逾時怎樣確認結果？重送、部分成功及重複回覆如何處理？ |
| 介面 | 必要畫面與欄位是什麼？有已與客戶驗證的HTML Mockup及其確認範圍嗎？有既有設計系統嗎？ |
| 品質 | 資料規模、裝置、併行與效能要求是什麼？有哪些資安與保留要求？有哪些代表性驗收資料？ |
| 開發交付 | 誰確認範圍、可行性與驗收？有哪些內外部依賴？上線、監控及復原條件是什麼？ |
| 治理 | 正式來源及生效規則是什麼？哪些未決？變更需要同步哪些圖、功能、案例與來源？ |
| 機器驗證 | 哪些目標可驗證？測試預期由誰確認？已有可執行規則或實作嗎？哪些案例不能測？ |

## 追加題庫的條件

- 多租戶、公司或倉別：問資料歸屬、跨範圍管理與下載權限。
- 金額或數量：問單位、分母、取整時機、守恆與對帳，不預設公式。
- 非同步：問進度、離頁恢復、取消、快照、逾時及結果不明。
- 演算法：問目標、硬／軟限制、無解與人工介入，不承諾優化器能力。
- 發布或外送：問版本、生效、重複防護、接收證據及舊版取代。
- 法規或合規：請窗口提供適用要求及正式依據，再由適合角色審閱。

## 確認點

1. 範圍確認：理解摘要、使用者、MVP、不做與來源優先序。
2. 設計確認：五層章節、功能卡、共用規則、狀態及流程圖、選用Mockup映射、目標測試預期、變更清單與未決邊界。
3. 交付審閱：產品規格、工程可行性與QA驗收分別留下證據。

只有作者明確授權可先做未決部分的展示時，才產出標明假設的概念方案；不能替作者選業務答案。真實副作用、正式來源更新與安裝不是上述確認的隱含授權。

所有不確定的產品要求由PM決策。資料來源、工程觀察或畫面存在，不代表核准。語意變更先列原文與提案差異；未核准只留在待決區，不自行套用。排版或等義短句整理可直接做，疑似改意即停止並問PM。
