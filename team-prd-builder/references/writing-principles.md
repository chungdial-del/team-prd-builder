# 精準寫作與五層解釋

## 受控繁中

ASD-STE100是Simplified Technical English。繁中PRD借鑑其受控語言原則，不宣稱取得認證或符合其英文詞典。官方依據：https://www.asd-ste100.org/STE_faq.html。

- 一個術語只代表一個意思。詞彙表列術語、定義與禁用同義詞。
- 一句表達一項要求。一個步驟只要求一項動作。
- 寫明執行者。優先使用「若條件成立，角色或系統執行動作，產生結果」。
- 固定「必須」「不得」「可以」的強制程度。改寫不得交換這三者。
- 刪除不承載條件的修飾。遇到「快速」「適當」「大部分」「自動處理」等未定義用語，列Q請PM定義，不自行填數值。
- 保留否定、單位、時區、公式、空／零、有效範圍、例外及拒絕後不變性。
- 不用機械截字或固定字數代替語意審查。自動檢查只能提供線索，不證明符合STE或業務正確。

改寫示例僅說明句型：「為了確保資料正確，系統應適當處理輸入」不能直接改成想像中的規則。先問驗證項目與拒絕結果。得到PM結論後，才寫明條件與結果。

## 圖表優先

讀者應先從圖理解主路徑。用流程圖表達任務與交接，用狀態圖表達允許或禁止的轉移，用時序圖表達要求與回應，用表格比較權限與決策條件。

每個狀態節點須定義物件。每條轉移須標事件、條件及結果。未決轉移連Q，不先畫成已核准路徑。不把業務狀態、外部接收狀態及需求核准狀態混成同一狀態機。

保留精簡圖解、圖例及FR／BR／AC追溯。圖不能取代數值邊界、公式、錯誤結果及測試預期。不要為提高圖片比例而增加沒有用途的圖。

## 整份文件的五層

| 層級 | 讀者需要知道什麼 | 主要章節 |
| --- | --- | --- |
| L1 白話目的 | 解決什麼問題；成功是什麼；本期不做什麼 | 摘要、問題、範圍 |
| L2 使用者任務 | 誰操作；從哪裡開始；在哪裡交接；如何完成 | 角色、歷程、操作流程 |
| L3 業務規則 | 功能邊界、資料、狀態、條件與可觀察結果 | 功能架構、共用規則、功能卡 |
| L4 系統互動 | 誰呼叫誰；如何處理非同步；哪些契約已確認 | 時序、已提供的技術契約 |
| L5 極限與驗證 | 邊界、併行、失敗、復原；如何反證錯誤行為 | 驗收、機器驗證、風險與決策 |

保留穩定章節ID。正文按閱讀深度排序，不依ID數字決定順序。章節可減少，但五層仍須有定位。缺少內容時寫明缺口與Q；不能新增想像中的部署、API或容量承諾。ELI5代表易懂，不代表使用幼兒語氣；PhD代表深入已知邊界，不代表加上無來源的學術術語。

## PM 決策門檻

允許直接做不改原意的排版、短句改寫及章節重排。保留原文映射。只要無法確定改寫是否等義，就列Q。

新增、刪除、改變角色、條件、預期、範圍或強制程度都屬語意變更。變更記錄列原文、提案、理由、受影響ID與Q，等待PM核准。沒有回覆不是同意。作者確認skill或文件格式，不代表核准各項業務答案。

確認決策須記錄PM、日期、原話或正式核准定位及範圍ID。工程或QA可確認自身審閱項，但所有不確定的產品要求仍交PM決策。不要以程式現況、客戶原型或AI推測代替PM結論。
